# HomeProxy1.14 融入 sing-box 1.14 特性 —— 设计文档

- 日期：2026-09-02
- 范围：`/Users/wjp/Downloads/homeproxy1.14`（luci-app-homeproxy，PKG_VERSION 1.14.0）
- 运行环境：ImmortalWrt 25.12.1（x86_64，apk），sing-box ≥ 1.14（仓库源已有 1.14.0-r1）
- 目标：把官方 sing-box 1.14.0（2026-08-30 发布）中与本 LuCI 透明代理相关的高价值特性融入本项目，同时保证稳定性
- 决策：**只面向 sing-box ≥ 1.14，不保留任何 1.13 兼容分支或兜底**

## 1. 背景与现状

官方 1.14 亮点中与本项目（OpenWrt/ImmortalWrt LuCI 透明代理 + 服务端）直接相关的主要有：

- DNS：`evaluate` / `match_response` / 响应字段匹配、`race` 并行竞争、乐观 DNS 缓存（`optimistic` + `store_dns`）、统一 `dns.timeout`、mDNS / `preferred_by` 等；
- 规则与规则集：`initial_path`（启动不被首次下载阻塞）、多 tag、`http_clients` 统一出站 HTTP 客户端（替代 `download_detour`）、`source_mac_address` / `source_hostname`；
- 连接层：TUN `dns_mode` / `dns_address`、UDP NAT 参数（`udp_mapping` / `udp_filtering` / `udp_nat_max`）、UDP pre-match 嗅探；
- 证书：内联 `tls.acme` 弃用 → `certificate_provider` 体系（ACME provider 新增 `account_key` / `key_type` / `profile` 等）；
- 工程化：配置 JSON Schema（`$schema`，运行时忽略，仅供编辑器校验）。

现状事实（勘查结论）：

- 路由器 192.168.1.1 为 ImmortalWrt 25.12.1，现装 luci-app-homeproxy **27.820.3-r3**（同源双兼容线）与 sing-box **1.13.21**；源里已有 **1.14.0-r1** 可升级；
- 27.820.3 是稳定在用的基线，可作为回滚基准；
- 本分拆线（1.14.0）已按 1.14 语义删掉一部分旧字段，但 README 路线图（evaluate/乐观缓存/规则集/http_clients/TUN/UDP NAT/证书/JSON Schema）尚未实现；
- 27.820.3 与上游目前也只做了“1.13/1.14 双兼容”修正，**没有实现上述 1.14 新特性**，因此本设计是全新功能开发。

## 2. 目标与非目标

### 目标

1. 配置生成端落地 1.14 新语义与新字段，覆盖“预设分流模式”与“自定义（custom）模式”两条代码路径；
2. LuCI UI 暴露新增能力，但**所有新增 UCI 选项默认值必须保持现有行为不变**；
3. 对 1.14 已弃用/删除的字段做语义等价迁移，不再生成会告警或被 1.14 拒绝的旧结构；
4. 增强启动可靠性：写配置前先 `sing-box check`、校验通过后原子替换；
5. 分批落地、分批提交、分批真机验证，保留回滚路径。

### 非目标（明确不做）

- 不做 sing-box 1.13 兼容：代码中不保留版本分支、双兼容开关或 1.13 兜底；
- 不做客户端型/重资源新子系统：OpenVPN（client/server）、OpenConnect、Snell、cloudflared、USB/IP、API 服务与 Dashboard、Desktop 客户端、L3 bridge、网络命名空间、Tailscale SSH/Taildrop、Windows/Apple TLS 引擎等——与 LuCI 透明代理场景无关，或需要 CGO/特权/图形客户端配合，风险高、收益低，另立任务再评估；
- 不改订阅解析框架、路由数据资源列表、打包/CI 主流程（除必要版本说明）；
- 不做整体 UI 重构（如改 tab 结构），只按需增改字段。

## 3. 稳定性原则（贯穿全部批次）

1. **默认值 = 现有行为**：任何新选项缺省时不改变生成的 JSON 与流量路径；新特性全部显式开启后才生效。
2. **1.14 合法优先**：不再生成 `independent_cache`、`store_rdrc`、DNS 规则 `strategy` 动作选项、`rule_set_ip_cidr_accept_empty`、内联 `tls.acme`、`download_detour` 等 1.14 已弃用结构；需要保留语义的用 1.14 等价结构表达。
3. **坏配置不落地**：`generate_client.uc` / `generate_server.uc` 先写临时文件 → `sing-box check` → 通过后原子 `mv` 到 `/var/run/homeproxy/sing-box-{c,s}.json`；失败保留上一份有效 JSON 并记日志。init 启动/重载沿用“校验不通过即中止”策略并补充版本前置校验。
4. **版本下限硬校验**：`/etc/init.d/homeproxy` 启动前解析 `sing-box version`，低于 1.14 直接记日志退出，给出明确提示，而不是生成被拒绝的配置。
5. **UI 不静默改写**：新增/迁移语义的选项在 UI 上有明确文案（含“1.14 迁移”说明）；旧配置不做破坏性 UCI 重写，尽量由生成器在内存中转换，保证降级与回滚简单。
6. **每批可独立验证**：每个批次一个提交，验证项见第 8 节；真机操作前必须备份配置与现有 apk/ipk，并有回滚步骤。

## 5. 批次 0：1.14 基线加固（工程底座）

目的：让“只面向 1.14”成为显式、可验证的基线，为后续批次提供安全落盘机制。

### 5.1 init.d 版本前置校验

- 在 `start_service()` 顶部解析 `sing-box version` 的 `major.minor`；小于 1.14 时 `log "Error: sing-box >= 1.14 required, found x.y.z."` 并 `return 1`；
- 现有启动尾部 `sing-box version -n` 保留；
- README 写明最低依赖：sing-box ≥ 1.14.0（对应 ImmortalWrt 源 sing-box 1.14.0-r1）。

### 5.2 原子落盘

- `generate_client.uc` / `generate_server.uc` 末尾改为：先写 `${RUN_DIR}/sing-box-{c,s}.json.tmp`，调用 `sing-box check --config <tmp>`，成功后 `mv` 替换正式文件；check 失败删除 tmp 并保留旧文件；
- 与 init 现有的 “无文件则报错退出” 逻辑衔接，不改服务编排顺序；
- 该改动使 reload 失败后即使重启也不会加载坏配置。

### 5.3 清除 1.13 残留（代码审计）

- 删除/改写 generate_client.uc 中为 1.13 设计的注释与分支占位（如 “legacy DNS fields … drop only in that case” 的条件逻辑改为 1.14 恒定语义，见批次 1）；
- 清理 uci-defaults/migrate 里只服务于旧内核的注释项，不保留双版本探测函数（不引入 `popen('sing-box version')` 式的运行时分支）。

### 5.4 交付物

- 提交 1：版本校验 + 原子落盘 + README 依赖说明；
- 验收：在 1.14 环境下 `sing-box check` 通过；人为降级 sing-box 至 1.13 时服务明确拒绝启动（后续真机阶段用临时降级验证一次，见 8.4）。

## 6. 批次 1：DNS、规则集与 http_clients（核心亮点）

### 6.1 custom 模式：1.14 DNS 规则能力

**UCI 扩展（dns_rule 段）**，新增字段（全部默认空/0，语义不变）：

- `action` 枚举扩展：`route` / `reject` / `predefined` 之外增加 `evaluate`、`respond`；route/reject 等规则增加 `race`（bool）、`speculative`（bool，配合前置 race）；
- 规则新增匹配项：`match_response`（bool 或 evaluate tag 字符串）、`response_rcode`、`response_answer`、`response_ns`、`response_extra`（DynamicList）、`query_client_subnet`、`query_dnssec`；
- route/evaluate/respond 动作新增：`timeout`（秒，可空）、`disable_cache`、`disable_optimistic_cache`、`remove_client_subnet`；
- 保留 `ip_cidr` / `ip_is_private` 输入，但 UI 文案改为“1.14 响应匹配”：生成器对含这些字段且无 `match_response` 的旧规则自动做等价转换（见 6.2），对新建规则推荐直接使用 evaluate + match_response。

**生成器（custom 分支）映射**：

- 规则输出按 `dns_rule` 顺序逐条展开；`match_response` 为字符串时原样输出为 tag；
- `ip_version` / `query_type` 规则与 legacy 字段同配置的冲突问题在 1.14 下不再“有条件丢弃”：生成器保证任何使用响应匹配/`evaluate` 的配置里都不输出 legacy 字段（`strategy` 动作选项、`rule_set_ip_cidr_accept_empty`）；
- DNS rule action 的 `strategy` 字段不再输出（1.14 弃用）；用户需要解析族偏好时使用 DNS 段全局 `default_strategy`（对应 uci `dns.default_strategy`，已有 UI），UI 中删除每规则的 strategy 选项并给出提示。

**UI（client.js DNS Rules tab）**：按 action 显示不同字段组；action=evaluate 时要求填 `server`（并新增可选 tag）；规则匹配字段分组增加“Response”tab；文案标注 Since 1.14。

### 6.2 旧 DNS 规则（legacy 地址过滤）自动等价迁移

目标：老配置里形如 `ip_cidr` / `ip_is_private`（无 match_response）的 DNS 规则，在 1.14 下会被拒绝。生成器做内存级自动包装：

- 扫描规则序列；对每条需要响应匹配的规则（含 legacy 地址过滤字段、或引用含 ip_cidr 的规则集），在其第一次出现位置之前插入一条顶层 `evaluate`（server 取该规则原 `server`，tag 使用内部名如 `_legacy_<idx>`）；
- 该规则输出时附加 `match_response: "<tag>"`；
- `rule_set_ip_cidr_accept_empty` 无 1.14 等价项：生成器忽略并写日志；migrate_config 删除该选项（幂等）；
- 纯“域名条件 + route”规则不受影响，保持原样输出。

说明：这是生成期的自动转换，不改写 UCI，避免破坏性数据迁移；若用户希望完全显式，UI 提供的新 action/字段可直接手写。

### 6.3 预设分流模式：国内 IP 兜底恢复（opt-in，默认关）

现状（fork 基线）：bypass_mainland_china 模式 DNS 规则为

1. direct 域名 → china-dns；
2. SVCB/HTTPS（qtype 64/65）→ reject；
3. NAPTR（qtype 35）特例 → default-dns；
4. proxy 域名 → main-dns；
5. geosite-cn → china-dns；final = main-dns。

1.13 时代的“响应为大陆 IP 则回国内 DNS”geoip 兜底已被 fork 以 1.14 拒绝为由删除。本批次用 1.14 方式恢复为**可选项 `cn_ip_fallback`（默认 '0'，保持现状）**：

当开启时，在规则 5 之后追加：

```json
{
  "action": "evaluate",
  "server": "main-dns",
  "tag": "cn-fallback"
},
{
  "match_response": "cn-fallback",
  "rule_set": "geoip-cn",
  "action": "route",
  "server": "china-dns"
}
```

final 仍为 main-dns。效果：漏出 geosite-cn 的国内域名若 main-dns 返回大陆 IP，会经国内 DNS 直连复解析；其余域名最终仍走 main-dns。UI 放在 client.js Routing 页（仅 bypass_mainland_china 可见），描述“1.14 evaluate/match_response 实现，默认关闭”。

为何默认关：该行为改变重复查询的 DNS 请求路径，需真机对比验证后再考虑翻转默认（稳定性原则 1）。

### 6.4 乐观缓存与统一超时

**UCI（dns 段，供 custom 与预设两模式共用读取）**：

- `optimistic_cache`：bool，默认 '0'（1.14 默认关，行为不变）；
- `optimistic_timeout`：如 `3d`/`1h`，默认空 → 不输出，用 sing-box 默认 `3d`；
- `dns_timeout`：秒/带单位，默认空 → 不输出（sing-box 默认 `10s`）；
- `cache_file_store_dns`：bool，默认 '0'（持久化 DNS 缓存，需 cache-file 启用时有效）。

**生成器**：

- `config.dns.optimistic`：`true` 时输出 `{"enabled": true, "timeout": <optimistic_timeout 或 3d>}`；与 `disable_cache`/`disable_expire` 互斥校验（UCI 校验：开启时强制 disable_cache=0）；
- `config.dns.timeout`：非空才输出；
- custom 分支 `independent_cache` 不再输出（1.14 起缓存恒按 transport 分键，删除即等价迁移）；`dns.independent_cache` UCI 选项从 UI 移除、migrate_config 幂等删除；
- `experimental.cache_file.store_rdrc`/`rdrc_timeout` 不再输出，改为 `store_dns: cache_file_store_dns`；UI 原 “Store RDRC/RDRC timeout” 替换为 “Store DNS cache”；migrate_config 把旧 `cache_file_store_rdrc=1` 转为 `cache_file_store_dns=1`（语义超集：旧值只存拒绝缓存，新值存完整 DNS 缓存）。

**UI（client.js DNS Settings tab，custom 显示；预设模式同步支持）**：optimistic、timeout、store_dns 控件；冲突选项 disable_cache/disable_expire 与 optimistic 互斥禁用提示。

### 6.5 规则集：initial_path 与多 tag

**UCI（ruleset 段）**：

- `initial_path`：Value（文件路径，仅 remote 显示），默认空 → 不输出；
- `extra_tags`：DynamicList，默认空；非空时与主 tag 一起输出（tag 数组），要求 `path`/`url` 含 `{tag}` 占位符（UI 校验提示）；inline 类型禁用。

**生成器**：按官方结构输出 `tag: [主tag, ...extra_tags]`（多 tag 时）、`initial_path`；无变化时保持单 tag 字符串，diff 最小。

### 6.6 http_clients（替代 download_detour）

现状：custom 模式 ruleset UI 的 `outbound`（每规则集）映射为远程规则集 `download_detour`。

**生成器自动迁移**：

- 遍历启用的 remote ruleset，收集去重后的 outbound 集合；为每个 outbound 生成一个顶级 http client：`http_clients: [{ "tag": "default"|"hp-<outbound>", "detour": <outbound> }]`（sing-box 1.14 顶层 http_client 使用扁平 `detour` 字段，不再包 `dial`；`hp-` 为保留前缀）；
- 远程规则集输出 `http_client: <对应 tag>`，不再输出 `download_detour`；
- 无任何 remote ruleset 时 `http_clients` 不输出（保持现状空配置 diff）。

UI：ruleset 段原有 `outbound` 字段保留，但描述改为“下载规则集所用出站（经 1.14 http_clients 生效）”；不引入新的 http 客户端参数编辑（路由器场景 YAGNI，后续需要再加）。

## 7. 批次 2：连接层（TUN/UDP NAT/规则项）

### 7.1 TUN dns_mode / dns_address

背景：1.14 默认 `dns_mode: hijack` 会设置系统接口 DNS 并装平台级劫持；本项目已通过 dnsmasq 把 53 端口导到 dns-in（5333）。ImmortalWrt 无 systemd-resolved，直接采用默认 hijack 可能与现有 dnsmasq 分流重叠，属于高风险改动。

设计：

- UCI（`config` 段，对应 UI Routing Settings tab；custom 与预设共用读取）新增 `tun_dns_mode`（ListValue：空=不设置/保持现状、disabled、native、hijack），默认空；
- `tun_dns_address`（DynamicList，IP），默认空；仅在显式设置 dns_mode 时生效；
- 生成器仅在 proxy_mode 含 tun 且选项非空时输出 `dns_mode`/`dns_address`；空时**不输出这两个字段**（等价于 1.13 行为：派生 DNS 地址自动劫持 + 现有 dnsmasq 逻辑不变）；
- UI 对 hijack/native 给出明确警告：“启用后由 sing-box 接管系统接口 DNS，与 dnsmasq 53 劫持可能存在重叠，仅在了解后果时开启”；
- 防火墙/init 的 dnsmasq 生成逻辑本批次不动（保持 dns_redirect 默认 1）。

### 7.2 UDP NAT 参数

- UCI（`config` 段，custom 与预设模式共用显示）：`udp_mapping`（endpoint_independent / address_dependent / address_and_port_dependent，默认空）、`udp_filtering`（同上）、`udp_nat_max`（整数，默认空）；
- 生成器：对 TUN、TProxy inbounds 以及 wireguard endpoint 输出共享 `udp_mapping`/`udp_filtering`/`udp_nat_max`（非空才输出）；已有 `udp_timeout` 逻辑不变；
- UI 位置：Routing 页（tproxy/tun 模式可见）+ custom routing 设置。

### 7.3 规则项：source_mac_address / source_hostname（custom 模式）

- route_rule / dns_rule UI 与生成器新增 `source_mac_address`（DynamicList，macaddr）与 `source_hostname`（DynamicList）；
- `source_hostname` 依赖邻居解析：routing 段新增 `find_neighbor`（bool，默认 '0'），开启时生成器输出 `route.find_neighbor: true`；未开启但使用 source_hostname 时 UI 校验提示（真机若无邻居数据，规则静默不命中，不会破坏其它规则）；
- 预设模式（重定向/TProxy）已有 nftables 层 MAC 分流，sing-box 层规则仅 custom/tun 场景生效，UI 文案注明适用范围。

### 7.4 无需代码即获得的能力（文档说明）

- UDP pre-match 嗅探：1.14 起 UDP 首包即可参与 sniff，本项目 route 已有全局 sniff 规则，无需改动；
- DNS `ip_version`/`query_type` 覆盖内部解析：已在 6.1 中按新语义输出，不再有 legacy 冲突。

## 8. 批次 3：证书体系与工程化收尾

### 8.1 generate_server.uc：内联 ACME → certificate_provider

- 输出结构由 `tls.acme` 改为：

```json
{
  "tls": {
    "enabled": true,
    "certificate_provider": {
      "type": "acme",
      "domain": [...],
      "data_directory": "/etc/homeproxy/certs",
      "default_server_name": "...",
      "email": "...",
      "provider": "...",
      "external_account": {...},
      "dns01_challenge": {...}
    }
  }
}
```

- 字段映射与现有 UCI（server 段 tls_acme_*）一致，不引入新 UCI 键（除 8.2 新增项）；
- 不再输出 `tls.acme`，README 记入迁移说明。

### 8.2 server UI 新增（可选字段，默认空）

## 10. 风险与对策

| 风险 | 对策 |
|---|---|
| TUN dns_mode 与 dnsmasq 劫持冲突 | 默认不输出该字段；UI 明确警告；真机单测 hijack 再决定是否推荐 |
| evaluate/race 语义复杂导致预设分流回归 | cn_ip_fallback 默认关；金样 diff + 真机 A/B |
| legacy DNS 自动包装顺序错误 | 生成器单测用例（构造 3 类旧规则验证输出序列与 check 通过） |
| http_clients 自动生成 tag 与用户自定义冲突 | tag 使用保留前缀 `hp-`；doc 说明；check 兜底 |
| 证书重构导致现有服务端失效 | 字段逐项映射 + 真机（或离线）`sing-box check`；保留内联字段到批次 3 才切换 |
| 新版依赖（quic-go/gVisor 等）间接行为变化 | 不主动升级路由内核之外的依赖；如遇异常记录并反馈上游 |
| 路由器操作影响在网用户 | 每次真机窗口先备份；选择低峰时段；具备一键回滚脚本 |
